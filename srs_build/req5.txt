## 5. Security requirements (SR)

TEXT: Each security requirement is a **SHALL** control whose parent is a **MUST** in `MCP_Gateway_Security_SRS.md` (cited as `SEC-n.n`). The ID `SR-<parent>-<k>` is the k-th child of that parent. The security SRS was written against the V1 architecture. Where its wording names a V1 component (for example "graph service", "supervisor", "admission worker"), the child below states the V2 element that realizes the control. MUSTs with no Gateway realization are listed with a disposition in Appendix E.

### SEC-1 Policy and routing authority

@SR-1-1 | Capability ceiling
P: SEC-1
S: The Policy Administration Service (E-05) SHALL reject publication of any grant whose tools, paths, egress destinations or secret slots exceed the capability ceiling of the referenced server revision's manifest.
A: E-05; E-14; F-10; I-07
V: Test | Publish grants exceeding each ceiling dimension; confirm each is rejected with the exceeded dimension named.
SRC: ARCH §7.3; ARCH §7.1 layer 1
R: The signed manifest bounds all authority.

@SR-1-2 | Layer intersection
P: SEC-1
S: The Policy Decision Service (E-06) SHALL permit a call only when it is permitted by every one of the Framework Profile, the Session Allow Policy as narrowed by session claims, and the request-time conditions.
A: E-06; F-13; I-05; I-08
V: Test | Run fixtures permitted by all but one layer, for each layer; confirm each is denied.
SRC: ARCH §7.1
R: Each layer can only remove authority.

@SR-1-3 | Template within profile
P: SEC-1
S: The Policy Administration Service (E-05) SHALL reject publication of a Session Allow Policy template that grants authority absent from every Framework Profile permitted to use it.
A: E-05; F-10
V: Test | Publish a template granting a tool its profiles lack; confirm rejection.
SRC: ARCH §7.3
R: Templates cannot widen profile authority.

@SR-1.1-1 | Single policy source
P: SEC-1.1
S: The Policy Decision Service (E-06) SHALL derive permit, deny, route, filter, audit and observation rules only from the active policy revision stored in the Graph Database Engine (E-25).
A: E-06; E-25; F-13; I-07; D-01
V: Inspection | Inspect the evaluator's inputs and configuration loading; confirm no file, environment or API path supplies rules.
SRC: SEC 1.1; ARCH §4 E-06
R: One authoritative source.

@SR-1.2-1 | Snapshot unavailability denial
P: SEC-1.2
S: When no validated decision snapshot of the active revision is loaded, the Policy Decision Service (E-06) SHALL return deny, and the Access Enforcement Point (E-08) SHALL return Gateway error `-31004`.
A: E-06; E-08; F-13; F-20
V: Test | Corrupt the snapshot at load; confirm every call is answered with -31004.
SRC: SEC 1.2
R: Fail closed.

@SR-1.2-2 | Data Server outage
P: SEC-1.2
S: When the Data Server cannot commit decision intent, the Enforcement Coordinator (E-12) SHALL refuse launch authorization.
A: E-12; E-26; F-29; I-30
V: Test | Stop the graph engine during traffic; confirm no dispatch occurs and -31004 is returned.
SRC: SEC 1.2; SEC 6.2
R: Dispatch requires durable intent.

@SR-1.3-1 | Default deny
P: SEC-1.3
S: When no applicable permit exists, the Policy Decision Service (E-06) SHALL return deny with reason code `NO_PERMIT`.
A: E-06; F-13
V: Test | Evaluate a request matching no permit; confirm deny with `NO_PERMIT`.
SRC: SEC 1.3
R: Allow-policy semantics.

@SR-1.4-1 | Deny precedence
P: SEC-1.4
S: When an applicable deny rule exists, the Policy Decision Service (E-06) SHALL return deny regardless of applicable permits.
A: E-06; F-13
V: Test | Evaluate fixtures with both a matching permit and a matching deny; confirm deny.
SRC: SEC 1.4
R: Deny wins.

@SR-1.5-1 | Prerequisite checks
P: SEC-1.5
S: The Policy Decision Service (E-06) SHALL deny a call whose principal is disabled, whose credential is expired or revoked, whose session is not active, whose server revision is not `enabled`, or whose tool has no explicit grant.
A: E-06; F-13; I-05
V: Test | Run one fixture per prerequisite failure; confirm deny with the matching reason code.
SRC: SEC 1.5; ARCH §4 E-14
R: Prerequisites gate evaluation.

@SR-1.6-1 | Exact match scope
P: SEC-1.6
S: The Policy Decision Service (E-06) SHALL match permits on principal or Framework Profile, session template, exact server revision ID, exact tool revision ID and MCP method.
A: E-06; F-13
V: Test | Change each dimension of a permitted request in turn; confirm each change results in deny.
SRC: SEC 1.6
R: No implicit widening.

@SR-1.7-1 | Predicate operator set
P: SEC-1.7
S: The Policy Decision Service (E-06) SHALL implement only the predicate operators exact equality, set membership, inclusive numeric range, canonical path containment, scheme/host/port membership, data-class membership, UTC expiry interval and approval state.
A: E-06; F-13
V: Test | Run the operator fixture suite; confirm each operator's semantics and that an unknown operator in a draft is rejected at validation.
SRC: SEC 1.7; SEC Appendix F
R: Typed, deterministic predicates.

@SR-1.7-2 | Missing attribute denial
P: SEC-1.7
S: When a predicate references a missing or malformed attribute, the Policy Decision Service (E-06) SHALL evaluate the rule as not matching for permits and SHALL deny the request.
A: E-06; F-13
V: Test | Omit an attribute referenced by a permit; confirm deny.
SRC: SEC Appendix F
R: Missing data cannot grant.

@SR-1.8-1 | Argument schema validation
P: SEC-1.8
S: The Request Inspection Pipeline (E-09) SHALL validate tool arguments against the manifest `inputSchema` and SHALL block the call with reason `SCHEMA` on failure.
A: E-09; F-21
V: Test | Send arguments violating type, required and additionalProperties constraints; confirm each is blocked.
SRC: SEC 1.8; MCP:server/tools §Security Considerations
R: Arguments must match the approved schema.

@SR-1.8-2 | Schema dialect handling
P: SEC-1.8
S: The Request Inspection Pipeline (E-09) SHALL validate JSON Schema 2020-12 and draft-07, SHALL treat any other dialect as a validation failure, and SHALL never dereference a network `$ref`.
A: E-09; F-21
V: Test | Validate against schemas of each dialect and one with an `https:` `$ref`; confirm the results and that no network access occurs.
SRC: MCP:basic/index §JSON Schema Usage; §$ref Resolution
R: Unsupported dialects and remote refs fail closed.

@SR-1.8-3 | Schema resource bounds
P: SEC-1.8
S: The Request Inspection Pipeline (E-09) SHALL abort schema validation that exceeds the CP-36 depth, subschema count or time bound and SHALL block the call.
A: E-09; F-21
V: Test | Validate against an exponential composition schema; confirm abort within the time bound.
SRC: MCP:basic/index §Composition-Keyword Resource Use
R: Schema denial-of-service defense.

@SR-1.8-4 | Path canonicalization
P: SEC-1.8
S: The Request Inspection Pipeline (E-09) SHALL canonicalize every path-typed argument by resolving `.`, `..` and symbolic links against the granted roots before path-containment evaluation.
A: E-09; F-21
V: Test | Submit traversal, symlink-escape and encoded-separator paths; confirm each is denied.
SRC: SEC 1.8; A2 §8 ENG-01
R: Path scope must use the real target.

@SR-1.8-5 | URL canonicalization
P: SEC-1.8
S: The Request Inspection Pipeline (E-09) SHALL canonicalize every URL-typed argument by normalizing scheme, IDNA host, port and IP-literal forms before destination-membership evaluation.
A: E-09; F-21
V: Test | Submit equivalent URL encodings of a denied host; confirm each is denied.
SRC: SEC 1.8
R: Destination scope must not be bypassed by encoding.

@SR-1.9-1 | Overlap rejection
P: SEC-1.9
S: The Policy Administration Service (E-05) SHALL reject publication of a revision containing overlapping permits whose argument scopes or obligations cannot be combined by the Appendix F precedence table.
A: E-05; F-10
V: Test | Publish two overlapping permits with conflicting routes; confirm rejection naming both rules.
SRC: SEC 1.9
R: Unambiguous grants.

@SR-1.10-1 | Obligation precedence
P: SEC-1.10
S: The Policy Decision Service (E-06) SHALL combine applicable obligations as the union of required filters, the smallest size, rate, time and resource bounds, the most restrictive approval, and the Appendix F retention and capture rules.
A: E-06; F-14
V: Test | Evaluate a request matched by rules with differing obligations; confirm the combined result.
SRC: SEC 1.10; SEC Appendix F
R: Conservative combination.

@SR-1.11-1 | Single route
P: SEC-1.11
S: The Policy Decision Service (E-06) SHALL select exactly one route bound to the evaluated server and tool revision and SHALL deny when zero or more than one route is eligible.
A: E-06; F-13; F-14
V: Test | Evaluate fixtures with zero, one and two eligible routes; confirm deny, permit and deny.
SRC: SEC 1.11
R: Deterministic routing.

@SR-1.12-1 | No semantic authorization
P: SEC-1.12
S: The Policy Decision Service (E-06) SHALL exclude full-text scores, vector similarity and model-generated content from permit and route selection.
A: E-06; F-13
V: Inspection | Inspect the evaluator inputs; confirm none of the excluded sources is reachable.
SRC: SEC 1.12
R: Authorization is deterministic.

@SR-1.12-2 | Restrict-only anomaly effect
P: SEC-1.12
S: The Policy Decision Service (E-06) SHALL apply anomaly bands only by adding obligations from the restrict-only action set and SHALL never convert a deny into a permit because of a band.
A: E-06; E-31; F-14; F-90; I-31
V: Test | Evaluate denied requests with `normal` bands and permitted requests with `critical` bands; confirm the denials stand and the permits gain restrictions.
SRC: ARCH §2.2 A-7; SEC 1.12
R: Statistics may restrict but never grant.

@SR-1.12-3 | Snapshot recording
P: SEC-1.12
S: The Policy Decision Service (E-06) SHALL record the baseline snapshot ID used for any anomaly obligation in the decision record.
A: E-06; F-13; F-16
V: Inspection | Inspect a decision with an anomaly obligation; confirm the snapshot ID.
SRC: ARCH §9.4 step 6
R: Reproducibility of statistical restrictions.

@SR-1.13-1 | Fixed query templates
P: SEC-1.13
S: The Data Access Service (E-26) SHALL execute only parameterized query templates from its versioned template set and SHALL reject caller-supplied query text, labels, relationship types or procedure names.
A: E-26; F-72; I-36; I-37
V: Test | Submit operations attempting to inject query text in each parameter; confirm rejection and no execution.
SRC: SEC 1.13
R: Prevents query injection.

@SR-1.13-2 | Template integrity
P: SEC-1.13
S: The Data Access Service (E-26) SHALL verify the digest of its template set against the release manifest at startup and SHALL refuse to start on mismatch.
A: E-26; F-72
V: Test | Modify one template file; confirm startup refusal.
SRC: SEC 1.13
R: Templates are reviewed code.

@SR-1.14-1 | Immutable revisions
P: SEC-1.14
S: The Policy Administration Service (E-05) SHALL reject every modification of a published revision, rule or route record.
A: E-05; E-26; F-12; I-07
V: Test | Attempt updates to published records through every API; confirm rejection.
SRC: SEC 1.14
R: Historical decisions remain explainable.

@SR-1.15-1 | Atomic activation
P: SEC-1.15
S: The Policy Administration Service (E-05) SHALL activate a revision by updating the policy-control record in one database transaction, and the Policy Decision Service (E-06) SHALL swap to the new snapshot only after that transaction commits.
A: E-05; E-06; E-25; F-12; F-13
V: Test | Crash the service at each step of activation; confirm the active revision is either the old or the new one, never mixed.
SRC: SEC 1.15
R: No partial policy.

@SR-1.16-1 | Coordinator serialization
P: SEC-1.16
S: The Enforcement Coordinator (E-12) SHALL serialize policy activation, revocation, emergency stop, launch authorization and release authorization through one gate.
A: E-12; F-29; F-30; F-31; F-32
V: Test | Race publication against launches with fault injection; confirm every launch is ordered entirely before or after the activation.
SRC: SEC 1.16; SEC Appendix F (coordinator ordering)
R: Closes policy races.

@SR-1.17-1 | Pre-launch recheck
P: SEC-1.17
S: Under the gate, the Enforcement Coordinator (E-12) SHALL recheck the policy revision, session state, credential state, server revision state and revocation epochs before issuing a launch capability.
A: E-12; F-29
V: Test | Revoke the credential between decision and launch; confirm launch refusal.
SRC: SEC 1.17
R: Decisions can become stale before launch.

@SR-1.17-2 | Pre-release recheck
P: SEC-1.17
S: Under the gate, the Enforcement Coordinator (E-12) SHALL recheck session state, revocation epochs and emergency-stop state before issuing a release authorization.
A: E-12; F-30
V: Test | Terminate the session during backend execution; confirm the result is withheld.
SRC: SEC 1.17
R: Authority can lapse during execution.

@SR-1.18-1 | Approval floor
P: SEC-1.18
S: The Policy Decision Service (E-06) SHALL require approval for every call to a tool whose manifest side-effect class is `write`, `external` or `execute`, or whose capability is in an Appendix F approval-trigger class.
A: E-06; F-14
V: Test | Call a tool of each class under a policy without approval rules; confirm the approval obligation.
SRC: SEC 1.18; SEC Appendix F (approval triggers)
R: A policy cannot remove the approval floor.

@SR-1.18-2 | Approval binding
P: SEC-1.18
S: The Approval Service (E-07) SHALL bind each approval to session, principal, server, tool and route revisions, canonical argument digest and policy revision, with an expiry of at most CP-17 and single use.
A: E-07; F-18
V: Test | Retry with a changed argument, another session, after a revision change and after expiry; confirm each is refused.
SRC: SEC 1.18
R: Approval authorizes exactly one request.

@SR-1.18-3 | Approval after transformation
P: SEC-1.18
S: When a request filter changes action-defining arguments of an approved call, the Approval Service (E-07) SHALL require a new approval bound to the transformed arguments.
A: E-07; E-09; F-17; F-21
V: Test | Redact a destination argument of an approved call; confirm a new approval is required.
SRC: SEC 1.18; SEC 5.12
R: The approver must see the final request.

@SR-1.19-1 | Decision explanation API
P: SEC-1.19
S: The Policy Decision Service (E-06) SHALL return, through `GET /api/v1/decisions/{id}/explanation`, the considered, applicable and decisive rule-revision IDs, selected route, effective obligations and anomaly evidence of a decision.
A: E-06; E-24; F-16; I-06
V: Test | Request explanations for permit, deny and anomaly-restricted decisions; confirm the contents.
SRC: SEC 1.19
R: Decisions are explainable.

@SR-1.20-1 | Evaluation bounds
P: SEC-1.20
S: The Policy Decision Service (E-06) SHALL deny an evaluation that exceeds the CP-12 deadline or candidate-rule bound, with reason code `EVAL_BOUND`.
A: E-06; F-13
V: Test | Construct a request matching 300 candidate rules and a slow-evaluation fixture; confirm deny with `EVAL_BOUND`.
SRC: SEC 1.20
R: Bounded decision work.

### SEC-2 Identity, credentials and administration

@SR-2-1 | Secrets never northbound
P: SEC-2
S: The Gateway SHALL exclude secret values from all X-01 traffic, including results, errors, progress notifications and session API responses.
A: E-02; E-11; E-20; X-01
V: Test | Deliver fingerprinted secrets in every mode and echo them through fixture outputs; confirm none reaches the harness.
SRC: ARCH §8.1 principle 1
R: The agent side never sees secrets.

@SR-2-2 | Researcher role limits
P: SEC-2
S: The Management Console & Control API (E-24) SHALL deny the Researcher role policy publication, approval decisions, secret operations, credential operations and S3 payload access without a campaign grant.
A: E-24; F-64
V: Test | Attempt each excluded operation as Researcher; confirm denial.
SRC: ARCH §4 E-24; Appendix C
R: Research access does not include control authority.

@SR-2.1-1 | Verified principal derivation
P: SEC-2.1
S: The Identity & Authentication Service (E-03) SHALL derive the principal of each request only from the client registration bound to a verified access token (FR-2.18), from the verified client certificate when the mTLS Harness Profile is enabled, or from the verified UDS peer and bearer key.
A: E-03; F-04; I-02
V: Test | Send requests with forged clientInfo and session-claim principal fields; confirm the principal is unchanged.
SRC: SEC 2.1
R: Identity from credentials only.

@SR-2.1-2 | Session token binding
P: SEC-2.1
S: The Identity & Authentication Service (E-03) SHALL reject with HTTP 401 and Gateway error `-31006` a session token presented on a listener other than the one it was issued for, or, when the mTLS Harness Profile or the UDS Harness Profile is enabled, over a connection whose client certificate thumbprint or UDS peer differs from the one bound at session creation.
A: E-03; E-04; F-05; I-02; I-04; X-01
V: Test | Replay a valid TLS-listener token over the UDS listener, and, with the mTLS profile enabled, from another certificate; confirm rejection of both.
SRC: SEC 2.1
R: Tokens are bound to their listener, and to the connection credential where one exists.

@SR-2.1-3 | Per-request authentication
P: SEC-2.1
S: The Identity & Authentication Service (E-03) SHALL authenticate every MCP and session-API request individually.
A: E-03; F-04; F-05
V: Test | Revoke a certificate mid-stream on a kept-alive connection; confirm the next request is rejected.
SRC: SEC 2.1
R: No connection-scoped trust.

@SR-2.2-1 | Independent credentials
P: SEC-2.2
S: The Key & Trust Anchor Manager (E-22) SHALL issue a distinct credential per framework instance, revocable without affecting other instances.
A: E-22; F-59
V: Test | Revoke one of two instances' credentials; confirm the other continues.
SRC: SEC 2.2
R: Containment of credential compromise.

@SR-2.3-1 | Bearer key generation
P: SEC-2.3
S: The Key & Trust Anchor Manager (E-22) SHALL generate UDS bearer keys, session tokens, access tokens, refresh tokens, authorization codes and client secrets from at least 256 bits of CSPRNG output and SHALL store only their SHA-256 verifiers.
A: E-22; E-04; F-59; F-06
V: Inspection | Inspect the generation code and stored records; confirm entropy and verifier-only storage.
SRC: SEC 2.3
R: Stored verifiers cannot be replayed.

@SR-2.3-2 | Adapter credential storage
P: SEC-2.3
S: The Harness Adapter Kit (E-33) SHALL store the principal credential and refresh token only in the CP-43 credential file with mode 0600 and SHALL refuse to start when that file is readable or writable by other users.
A: E-33; F-94; X-12
V: Test | Set the file to mode 0644; confirm the adapter exits with an error naming the file and makes no connection.
SRC: SEC 2.3; CP-43
R: The adapter holds the only copy of a framework credential on the harness host.

@SR-2.4-1 | Revocation latency
P: SEC-2.4
S: The Enforcement Coordinator (E-12) SHALL prevent new launch authorization for a revoked credential, session or principal within CP-16 of the revocation.
A: E-12; F-32; I-20
V: Test | Revoke under load; confirm no launch for the revoked identity later than CP-16.
SRC: SEC 2.4
R: Timely revocation.

@SR-2.5-1 | Admin endpoint separation
P: SEC-2.5
S: The Management Console & Control API (E-24) SHALL serve the control API only on the CP-03 admin listener and SHALL reject harness client certificates and session tokens.
A: E-24; F-63; X-04
V: Test | Present harness credentials to the control API; confirm rejection.
SRC: SEC 2.5
R: Agents cannot reach administration.

@SR-2.6-1 | Admin session profile
P: SEC-2.6
S: The Management Console & Control API (E-24) SHALL implement administrative sessions with server-side random IDs, `Secure`, `HttpOnly` and `SameSite=Strict` cookies, ID rotation on login and privilege change, immediate logout invalidation, and the CP-29 idle and absolute limits.
A: E-24; F-63
V: Test | Verify each property, including that a pre-login session ID is not preserved.
SRC: SEC 2.6; SEC Appendix F
R: Protected administrator sessions.

@SR-2.7-1 | Password hashing
P: SEC-2.7
S: The Management Console & Control API (E-24) SHALL store administrator passwords only as Argon2id verifiers with the CP-28 parameters.
A: E-24; F-63
V: Inspection | Inspect stored verifiers and parameters.
SRC: SEC 2.7
R: Password confidentiality.

@SR-2.8-1 | TLS profile
P: SEC-2.8
S: The Harness Interface Endpoint (E-01) and the Management Console & Control API (E-24) SHALL accept only TLS 1.3 connections using certificates issued by the Gateway server CA for the configured listener names.
A: E-01; E-24; F-01; X-01; X-04
V: Test | Attempt TLS 1.2 and a mismatched name; confirm failure.
SRC: SEC 2.8
R: Authenticated transport.

@SR-2.8-2 | Mutual TLS
P: SEC-2.8
S: When the mTLS Harness Profile is enabled, the Harness Interface Endpoint (E-01) SHALL require a client certificate chaining to the Gateway client CA on the TLS harness listener.
A: E-01; F-01; X-01
V: Test | Enable the profile; connect without a certificate and with a foreign certificate; confirm rejection during the handshake.
SRC: SEC 2.8; ARCH §19 OD-2
R: Optional transport-level framework authentication for harnesses that can present a client certificate.

@SR-2.8-3 | UDS permissions
P: SEC-2.8
S: The Harness Interface Endpoint (E-01) SHALL create the UDS harness socket with mode 0660 owned by the `smcp-harness` group.
A: E-01; F-01
V: Inspection | Inspect the socket ownership and mode.
SRC: SEC 2.8
R: Local transport access control.

@SR-2.9-1 | Origin validation
P: SEC-2.9
S: When a request carries an `Origin` header that is not in the configured allowlist, which is empty by default, the Harness Interface Endpoint (E-01) SHALL respond with HTTP 403.
A: E-01; F-01; X-01
V: Test | Send requests with a foreign Origin; confirm 403.
SRC: SEC 2.9; MCP:basic/transports/streamable-http §Security
R: DNS-rebinding defense.

@SR-2.9-2 | Host validation
P: SEC-2.9
S: The Harness Interface Endpoint (E-01) and the Management Console & Control API (E-24) SHALL reject requests whose `Host` header is not a configured listener name.
A: E-01; E-24; F-01; X-01; X-04
V: Test | Send requests with a foreign Host; confirm rejection.
SRC: SEC 2.9
R: DNS-rebinding defense.

@SR-2.9-3 | Loopback binding
P: SEC-2.9
S: The Harness Interface Endpoint (E-01) and the Management Console & Control API (E-24) SHALL bind only to loopback addresses unless the Overlay Profile is enabled.
A: E-01; E-24; F-01
V: Inspection | Inspect bound addresses in the default configuration.
SRC: MCP:basic/transports/streamable-http §Security; SEC 4.14
R: Local-only exposure by default.

@SR-2.10-1 | Credential separation
P: SEC-2.10
S: The Tool Dispatcher (E-10) SHALL exclude northbound credentials, session tokens and `Authorization` headers from southbound requests.
A: E-10; F-23; I-13
V: Test | Capture southbound traffic; confirm no northbound credential material.
SRC: SEC 2.10
R: No credential forwarding.

@SR-2.11-1 | OAuth token validation
P: SEC-2.11
S: The Identity & Authentication Service (E-03) SHALL validate access tokens per the MCP 2026-07-28 authorization specification, including audience binding to the CP-41 resource URI, and SHALL reject tokens failing validation.
A: E-03; F-04; X-01
V: Test | Run the authorization conformance fixtures, including wrong-audience, expired and revoked tokens.
SRC: SEC 2.11; MCP:basic/authorization; CP-41
R: Standards-based authorization is the baseline harness authentication.

@SR-2.12-1 | Handle ownership
P: SEC-2.12
S: For a tool with a manifest handle contract, the Access Enforcement Point (E-08) SHALL record handles created by results with their owning session and principal, and SHALL deny calls presenting a handle owned by another session or principal or past its expiry.
A: E-08; E-11; F-20; F-27
V: Test | Create a handle in session A and use it from session B and after expiry; confirm denial.
SRC: SEC 2.12; MCP:server/tools §Stateful Tools
R: Handles are names, not capabilities.

@SR-2.13-1 | Vault encryption
P: SEC-2.13
S: The Secret Vault (E-19) SHALL encrypt each secret value with age to the vault master key held by the Key & Trust Anchor Manager (E-22).
A: E-19; E-22; F-47; F-60
V: Inspection | Inspect the vault store; confirm age ciphertext and no plaintext.
SRC: SEC 2.13
R: Encrypted at rest.

@SR-2.13-2 | Plaintext lifetime
P: SEC-2.13
S: The Secret Broker (E-20) SHALL hold decrypted secret values only in memory for the duration of a delivery and SHALL overwrite the buffers after use.
A: E-20; F-50
V: Inspection | Review the delivery code path and a memory snapshot after delivery.
SRC: SEC 2.13
R: Minimizes plaintext exposure.

@SR-2.13-3 | Vault isolation
P: SEC-2.13
S: The Secret Vault (E-19) SHALL be readable only by the Secret Broker (E-20) service identity.
A: E-19; E-20; I-27
V: Test | Attempt vault reads as every other service identity; confirm denial.
SRC: SEC 2.13; ARCH §4 E-19
R: Data Server compromise does not expose secrets.

@SR-2.14-1 | Backend environment allowlist
P: SEC-2.14
S: The Server Runtime Manager (E-15) SHALL build each instance environment only from the manifest variable allowlist, the Gateway-generated egress endpoint variables and approved S4 secrets.
A: E-15; F-38
V: Inspection | Inspect a launched instance environment against its manifest.
SRC: SEC 2.14
R: Minimal environment.

### SEC-3 Verified server provenance

@SR-3-1 | Signature verification
P: SEC-3
S: The Library Trust Verifier (E-13) SHALL accept a package only when its signature verifies under an enrolled, unexpired trust anchor whose scope includes the manifest risk class.
A: E-13; E-22; F-33; I-17
V: Test | Import packages signed by an unknown key, an expired anchor and an out-of-scope anchor; confirm rejection.
SRC: ARCH §4 E-13; ARCH §2.1 item 1
R: Only curated servers run.

@SR-3-2 | Artifact digest verification
P: SEC-3
S: The Library Trust Verifier (E-13) SHALL verify that each artifact's SHA-256 digest equals the digest in the signed manifest, at import and at every instance launch.
A: E-13; E-15; F-33; F-38; D-03
V: Test | Alter an artifact after import; confirm the next launch is refused and the revision is suspended.
SRC: ARCH §4 E-13; CP-35
R: The running artifact is the signed artifact.

@SR-3-3 | Revocation processing
P: SEC-3
S: The Library Trust Verifier (E-13) SHALL mark a revoked package's server revisions `revoked` within 60 seconds of reading the revocation entry.
A: E-13; E-14; F-35
V: Test | Publish a revocation entry; confirm the state change and instance teardown within 60 s.
SRC: ARCH §18.8
R: Curation revocation takes effect.

@SR-3-4 | Revocation feed staleness
P: SEC-3

### SEC-7 Safe operation and recovery

@SR-7-1 | Baseline integrity
