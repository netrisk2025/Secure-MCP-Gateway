- Known issue, found by the runbook executions for v1.1.0 (`docs/verification/runbooks/runbook-key-rotation-2026-10-18.md`): after a CA switch (`smcpctl keys rotate ca --finish`, `--overlap 0`, or at `switch_at`), `ca.crt` holds only the new CA at once, but the listeners serve the old certificate for up to one second. `keys.CertReloader` checks the certificate file at most once per second, and the rotation does not call `Reload`. During that second, a client that trusts only the new bundle fails with `x509: certificate signed by unknown authority`. The key-rotation and key-compromise runbooks now say to wait a second before checking a client.

## v1.0.0 — 2026-10-18

First release of the Secure MCP Gateway, built to SRS V1.2 and architecture V2.3. The sections below this one record how it was specified and built; this section is the release note. The tag is made by the procedure in `docs/release-checklist.md` after the phase-8 pull requests.

### What is in the release

- `smcpd`, the Gateway daemon: an MCP endpoint for local agent harnesses (Streamable HTTP over TLS on loopback, OAuth with Session Approver sign-in), the signed Policy Store and decision point, tool-call approvals with hold mode, request and response inspection, the package library with signed packages and trust anchors, the Secret Vault and Secret Broker, the Egress Broker, the Evidence Journal (hash-chained, signed) with export, health monitoring, the management console (embedded), observation with anomaly scoring, the optional Neo4j graph mirror and the Remote Access Profile for cloud agents.
- `smcpctl`, the administrative CLI, including the new `smcpctl install` (below), `upgrade` with backup and rollback, and `uninstall` with `--purge`.
- `smcp-refserver` (the packaged example server), the harness adapters `smcp-session` and `smcp-stdio`, and `smcp-connect` for cloud agents (also on npm).
- Platforms: macOS (arm64, amd64) and Linux (amd64, arm64). The Enforced profile (every server in a rootless Podman sandbox under systemd, nftables and AppArmor) runs on Linux; macOS and Linux hosts without the prerequisites run the Standalone profile, labelled "not enforced", with health `degraded: unconfined`.
- Agents tested end to end through the Gateway: Claude Code, Codex, Hermes, OpenCode and Goose (`docs/agents-conformance.md`).
- Element state: every element E-01 to E-33 is wired into `smcpd`. E-07 (Approval Service), E-09 (Request Inspection Pipeline), E-17 (Runtime Monitor), E-30 (Behavior Baseline Engine) and E-31 (Anomaly Scorer) are recorded as implemented, because every requirement allocated to them is verified, none is deferred and no other gap is known; the other 28 are partial (`docs/status/elements.json`).

### Policy model: argument predicates, prerequisites, routes, high-risk flags, obligation types (E-05, E-06)

- Argument predicates (SR-1.7-1, SR-1.7-2, FR-3.6): a permit rule may carry `when`, a list of predicates from the fixed operator set `eq`, `in`, `range`, `path_within`, `url_in`, `data_class_in`, `expiry` and `approval`; the rule permits only when all hold, and a missing or malformed argument makes it not match (`NO_PERMIT` with the failed predicate in the decision record). - Prerequisites (SR-1.5-1): the decision denies a disabled principal (`PRINCIPAL_DISABLED`), an invalid credential (`CREDENTIAL_INVALID`), an inactive session (`SESSION_STATE`) and a server revision that is not enabled (`REVISION_NOT_ENABLED`) before evaluating rules.

### Intermittent test failures fixed at their cause

- Baseline candidate state: concurrent saves (the record-count build, the interval loop and `Close`) shared one `.tmp` path, so one save could rename another's partly written file into place or fail with "no such file". Saves are now serialized and each writes its own temporary file; snapshot builds are serialized whatever their trigger, and `Manager.Wait` (also called by `Close`) waits for background builds. `TestSnapshotTriggersAndImmutability` waits for the build events and for `Run` to return instead of polling the snapshot list; new `TestSaveStateConcurrent`.
- Runtime Monitor: the first cgroup sample was taken as the baseline of the memory and pids event counters, so a limit hit between the container start and the first sample (a fork bomb at startup) was not a breach. Each instance has a fresh container cgroup whose counters start at zero, so the baseline is now zero. New `TestMonitorKillsOnPidsBreachBeforeFirstSample`.
- `internal/testport` reserves each port it hands out for the life of the process with a lock on one byte of a shared file, so parallel test processes never get the same port; `testport.Port` serves non-test programs. `scripts/agents` and `console/e2e/gateway.ts` choose listener ports below the ephemeral range instead of from port 0, where smcpd's own port-0 egress proxy could take the configured metrics port first ("address already in use" at startup).
- `TestDeviceGrant` runs the remote access service on a clock the test moves (`gwtest.StartWithRemoteClock`), so the device-code poll interval no longer depends on how long client authentication takes under `-race`; it now also checks that polling is allowed again after the interval.
- The observation end-to-end fixture (`internal/e2e`) gives its subprocess backend 30 s instead of 2 s per call; one of 66 local `-race` runs of `TestObservationThroughGateway` under load ended a call with "upstream timeout". No observation test exercises the timeouts.
- G-04 preview table: the record time is always shown and sorts, and unmasked parameter columns sort, so the table has a sortable column whatever the selection (the console style check failed when two or more records were stored).

### Protocol hardening after the hostile suite (phase 4)

- Progress relay (FR-1.39, FR-1.40, SR-5.9-1): a `tools/call` with a `progressToken` sends the backend a Gateway-issued token and relays the backend's `notifications/progress` with the northbound token, strictly increasing values, at most 10 per second per request (CP-21) and none after the response. Each message passes the response filters first (blocked: dropped; transformed: relayed as transformed) and carries provenance with the filters applied and any tags. The frame filter routes progress in line order, so notifications written before the response are relayed before it; a bounded queue keeps a slow harness from stalling a shared instance. Approval keep-alives share the call's progress sequence.
- Instance restart (Appendix L HF-17, HF-19): a call that reaches the upstream timeout (`-31009 UPSTREAM_TIMEOUT`) or finds the instance gone replaces the instance; later calls wait for the new one. A relaunch that fails or presents a different revision suspends the server.
- `InputRequiredResult` from a backend ends the call with `-31010 INPUT_REQUIRED_UNSUPPORTED` and a `failed` event (FR-5.24); the MRTR Relay Profile is not implemented.
- Server-initiated requests other than `ping` (`roots/list`, `sampling/createMessage`, `elicitation/create`) are answered with `-32601` by the Gateway and never reach the SDK client (FR-5.20); the Gateway declares no client capabilities southbound (SR-5.6-2), where the SDK used to declare `roots`.
- Public-name collisions (FR-1.49) and the other per-revision presentation errors no longer stop the Gateway: the revision is not enabled, `Registry.Disabled` keeps the reason naming both tools, and a `not_enabled` event (`SERVER_NOT_ENABLED`) is recorded.
- Enforced profile: the Secret Broker's S2/S3 directory is mounted read-only at `/smcp/secrets` and the file-path variables are rewritten, so a sandboxed server can read its secret files (the cause of HF-08 failing in the Enforced run: the fixture could not read the file, so there was nothing to block). Such a server needs `userns = "keep-id"`; with `"auto"` the launch is refused with that reason.
- FR-1.10 is verified: unknown methods answer HTTP 404 with `-32601` in the 2026-07-28 era (the SDK already did this; the note saying otherwise was stale), and HTTP 200 in the legacy era.
- `make hostile` (Standalone): 23 of 27 rows pass; the other four are Enforced rows.
- Tests: `TestObserveCommands` waits for the observation writer through the new `analytics.Service.Sync` instead of sleeping 50 ms; the approval e2e tests poll for the evidence that the audit observer queue delivers asynchronously instead of reading it once.
