Steps:

1. Set the repository variable `SMCP_TAP_PRERELEASE=true` so that GoReleaser pushes the formula for a pre-release (`.goreleaser.yaml`, `brews.skip_upload`).
2. Tagged v1.0.0-rc.2 on main `4ba2189`. The release workflow (run 39032406916) published the release and pushed `Formula/smcp.rb` to `ethan03805/homebrew-tap` (commit `db9a71d`, message `smcp v1.0.0-rc.2`), then dispatched the `tap` workflow.
3. The `tap` workflow (run 39032895870) ran on macos-latest and ubuntu-latest: `brew tap ethan03805/tap`, waited for formula version 1.0.0-rc.2, `brew install ethan03805/tap/smcp`, `brew test ethan03805/tap/smcp`, `smcpd --version`, then `install.sh --version v1.0.0-rc.2` into a separate directory (minisign signature and archive checksum verified) and compared the SHA-256 of each of the six binaries.

Observations:

- Both jobs passed. On both runners the formula's archive URL and SHA-256 matched the release: Homebrew downloaded the release archive and installed it.
- macOS (darwin-arm64): `smcpd`, `smcpctl`, `smcp-refserver`, `smcp-session`, `smcp-stdio` and `smcp-connect` equal to the archive's (for example `smcpd` a62c10d699b1719a3e85de5366376200cff6748d110a38988359db1e4fdd3d92). install.sh verified with minisign.
- Ubuntu (linux-amd64): the six binaries equal to the archive's (for example `smcpd` fd522ed67ac77d6dec6423525df8c073bf5ed6467e03a323c547e0ec5aa1a621). install.sh verified with OpenSSL 3.

Deviation: the run used a release candidate published with `SMCP_TAP_PRERELEASE=true`; the variable was deleted afterwards so that later pre-releases do not replace the formula. The `tap` workflow runs again for v1.0.0, dispatched by the release workflow.
